# 0.6.1 startup JSON compatibility hotfix

Mono.Cecil metadata reproduces missing one-argument `ToString` and `WriteTo` members in the game's JSON library; both game and loader libraries have assembly identity 13.0.0.0, so version-number checks alone missed it.

The fix uses `UiDataJson.Serialize` for startup resources, with an explicit converter array for the older writer overload, and compiles against the game's Managed .NET Standard 2.0 JSON API. Build-time `tools/check-json-compatibility.ps1` resolves all 17 Json.NET type and 42 member references separately against both actual dependency files (118 resolutions). The released 0.6.0 DLL fails this check at both missing overloads as expected. Both actual libraries pass 11 standalone startup-resource/serializer checks and 613 security checks each. The game library is byte-identical to the installed copy and runs in a .NET 8 test host; a .NET Framework host rejected its strong-name signature before running the tests. The loader copy runs in .NET Framework 4.8. No signature-verification setting, game file or loader dependency was altered. These hosts check data handling and do not emulate Unity/Mono or a game session.

Keyboard behavior and layout are unchanged from 0.6.0 apart from version labels. The 75 keyboard-engine and 637 event checks pass again; previous 40 keyboard-UI/78 interface and 1505 rendering/145 lifecycle fixture checks remain historical evidence, not new live-client checks. All 1037 checks in the 13-project suite pass again for the helper change. Ten embedded resources and installer payload/version checks pass. Actual game restart/UI recovery, Cohtml, IME/Win+H, PC/VR and long sessions require client testing.
